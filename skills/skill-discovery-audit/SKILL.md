# /skill-discovery-audit — weekly skill usage vs inventory audit

## What it answers

> "I've installed 400+ skills. Which ones did I actually use this week? Which ones SHOULD I have used but didn't?"

Twin to `/claude-this-week`: that one watches the external world; this one watches the user's own behavior.

## Hard rules

1. **Ground every claim in session jsonl evidence.** Quote the exact `tool_use` or text where the skill was/wasn't invoked. No "I think you used X" — show the line.
2. **Domain inference uses the same `specialist-map.json`** the C6 hook uses — single source of truth.
3. **Bias toward UNDER-recommending** (mention 3–5 high-confidence misses, not 20 marginal ones). the user's attention is the constraint.
5. **No "score" or "grade."** This is intelligence-gathering, not performance review.

## Procedure

### Step 1 — anchor the window

```bash
TODAY=$(date +%Y-%m-%d)
WEEK_AGO=$(date -d '7 days ago' +%Y-%m-%d)
OUT_DIR="~/data/artifacts/project-assistant-renew/skill-discovery/${TODAY}"
mkdir -p "$OUT_DIR"
```

### Step 2 — enumerate this week's sessions

```bash
find ~/claude-archives/sessions/ -name '*.jsonl' \
  -newermt "$WEEK_AGO" 2>/dev/null \
  | sort
```

### Step 3 — extract usage signal per session

For each session jsonl, parse:
- Slash-command invocations (`<command-name>` blocks in user messages)
- `Skill` tool calls (assistant invokes a named skill via Skill tool)
- `Agent` tool dispatches with `subagent_type` (which specialist used)
- Free-text mention of domains (regex against `specialist-map.json` patterns)
- Project context (most-edited project dir in the session, infer from `Edit`/`Write` tool calls)

Write per-session JSON to `$OUT_DIR/raw/<sid>.json` with shape:

```json
{
  "sid": "...",
  "date": "YYYY-MM-DD",
  "duration_minutes": N,
  "slash_commands_used": ["/foo","/bar"],
  "skills_invoked": ["skill-a","skill-b"],
  "agents_dispatched": ["python-systems-engineer","Explore"],
  "domains_mentioned": ["n8n","vllm","qdrant"],
  "project_context": "~/projects/...",
}
```

### Step 4 — aggregate

Reduce per-session JSON into a weekly summary:

- `unique_skills_invoked` — set
- `unique_agents_dispatched` — set
- `domain_frequency` — `{n8n: 4, vllm: 7, qdrant: 1, ...}`
- `top_project_contexts` — top-3 by edit count

### Step 5 — diff against installed inventory

Read the FULL installed-skills list from the current Claude Code system reminder (or `~/.claude/skills/` + plugin marketplaces). For each domain in `domain_frequency` with count ≥ 2:

- List skills whose name OR description references that domain
- Subtract any that ARE in `unique_skills_invoked`
- Remaining = "skills you have that you didn't use, in domains you worked in this week"

Per the hard rules: cap at top 5 highest-confidence matches.

### Step 6 — synthesize report

Path: `$OUT_DIR/README.md`

Schema:

```markdown
# Skill Discovery Audit — week ending <YYYY-MM-DD>

## Headline
You ran <N> sessions / <H> hours of focused work this week.
<short opinionated lede — what was the dominant domain? Where might Will be repeating effort?>

## Domain frequency (top 5)
| Domain | Mentions | Skills you DID use | Skills you DIDN'T |
|---|---|---|---|
| n8n | 14 | n8n-architect (1×) | n8n-workflow-patterns, n8n-validation-expert |
| ... |

## Highest-confidence misses (cap 5)
1. **<skill-name>** — would have helped during: <session-sid + one-line context>. Why it fits: <one line>.
2. ...

## Skills used most this week (sanity check — verify these are still serving you)
- <skill> (N uses)

## Suggested auto-suggest additions
Phrase patterns that would route to a frequently-missed skill via the C6 specialist-suggester hook. Edit `~/.claude/specialist-map.json` to add (Will to approve before commit).

| Phrase regex | Target skill | Why |
|---|---|---|

## Aggregate non-itemized stats
- Total user messages: <N>
- Total tool calls: <N>

## Sources
- N session jsonls under ~/claude-archives/sessions/YYYY-MM-DD/
- specialist-map.json (current revision: <mtime>)
- Per-session raw extracts: ./raw/

---
*Generated by /skill-discovery-audit on <date> · sibling to /claude-this-week*
```

### Step 7 — append to index

Append one row to `~/data/artifacts/project-assistant-renew/skill-discovery/README.md`:

```
| <week-of> | [<week-of>](./<week-of>/README.md) | <headline-1-liner> | top miss: <skill-name> |
```

```cron

```

Removal: `crontab -l | grep -v skill-discovery-audit | crontab -`

## Anti-self-praise rule

The first version of this skill (drafted in spec) said "you used 47 skills this week — great variety!" the user's revision deleted that. The report shows GAPS and MISSES, not pats on the back. If the audit week has nothing to surface (Will used every relevant skill perfectly), the report says: "Nothing flagged this week. Either you're crushing it or this auditor needs better detection."
